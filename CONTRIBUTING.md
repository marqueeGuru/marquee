# Contributing to Marquee

Thanks for your interest. The project is early and the most useful contribution right now is **conversation** — questions, framings, dissents, prior art we should know about, machines and tools we should think about modeling.

## Where to put what

- **Open-ended thoughts, questions, "have you considered X"** → [GitHub Discussions](../../discussions). Public, no approval, low friction.
- **A concrete proposal** (a feature, a scope change, a roadmap item) → open a [GitHub Issue](../../issues/new/choose) using the *Proposal* template.
- **A reproducible bug** in the emulator or this site → open a [GitHub Issue](../../issues/new/choose) using the *Bug report* template.
- **Sustained back-and-forth** with the maintainer → Telegram (joining soon).

## Code contributions

Code contributions are welcome, but the API surface is not stable. Please open an Issue **before** writing a non-trivial patch — coordinating early saves everyone time, and it gives us a record to reference once the codebase grows.

For small, obvious fixes (typos, broken links, dead docs), a PR without a prior issue is fine.

## What kinds of input are most welcome right now

- **Manufacturing experience.** First-hand knowledge about lathe operations, tooling, fixturing, real-world failure modes — especially things that are not in textbooks.
- **EDA / chip-design analogues.** If you've worked on logic emulation, design-rule checking, or DFM tooling for silicon, the analogy this project leans on is yours to sharpen or push back on.
- **Open-source community know-how.** How to set up healthy participation, governance, and curation as the project grows.
- **CAD / geometry kernel experience.** Especially around STEP, NURBS, axisymmetric profiles, and feature recognition.
